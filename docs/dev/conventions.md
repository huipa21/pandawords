# Conventions

## General

- English for code, comments, docs and commit messages. UI text goes through i18n.
- Times are UTC everywhere (DB and API, ISO 8601 with `Z`). Convert to local time only for display.
- Files stay under about 300 lines. Split by responsibility, not by layer type.
- Comments only where the code needs clarification.

## Python

| Item | Convention |
|---|---|
| Format / lint | ruff (`ruff format`, `ruff check`), line length 100 |
| Types | basedpyright. Every function is typed. No `Any` in public signatures |
| Names | modules `snake_case`, classes `PascalCase`, functions `snake_case`, constants `UPPER_SNAKE` |
| Models | `XxxCreate` / `XxxUpdate` / `XxxRead` (API), `Xxx` (internal) |
| Async | Everything that touches I/O is async. No blocking calls in request handlers (run CPU-heavy spaCy work via `anyio.to_thread`) |
| Errors | Domain exceptions carry an error `code` like `project.not_found` |

## TypeScript / Vue

| Item | Convention |
|---|---|
| Format / lint | `@antfu/eslint-config` (it formats too; no Prettier) |
| Files | components `PascalCase.vue`, composables `useXxx.ts`, stores `xxx.store.ts` exporting `useXxxStore` |
| SFC order | `<script setup lang="ts">` → `<template>` → `<style scoped>` (rarely needed; prefer Uno classes) |
| Props | `defineProps<{...}>()` with TS types. Emits are typed too |
| Imports | `@/` alias for `src/` |

## API

- Regenerate the committed frontend contract with `.\scripts\dev.ps1 gen-api`: offline
  `uv run --offline python -m app.openapi` exports JSON without starting the API or database,
  then local `openapi-typescript` generates `frontend/src/api/schema.d.ts`. Both outputs belong
  to the invoking worktree (unlike setup's main-worktree targets); ESLint formats the outputs.
  Never edit generated types. `openapi-typescript` 7.13 declares a TypeScript 5 peer range,
  so pnpm warns with our pinned TypeScript 6; generation, typecheck and build are verified on 6.
- Use `createApiClient` from `frontend/src/api/client.ts`. Its optional `auth` lifecycle reads
  the access token, refreshes/persists it, and clears local auth state on refresh failure.
  Concurrent 401s share one refresh, including late responses, and requests retry at most once.
  Error responses are normalized to `{code, message, field}`; `readApiError` also accepts raw
  responses. Auth is opt-in until task 1.5.3 adds the actual endpoints: regenerate the contract
  then wire lifecycle callbacks using those generated types, not placeholder endpoint types.
  Refresh must use a separate non-recovering client; configure `shouldRefresh` to exclude
  login/refresh requests. No token persistence or auth store is imposed by this layer.

- Prefix `/api`. Resources are plural nouns: `/api/projects/{id}/words`.
- **IDs in the API** are opaque URL-safe strings (`rid`): base64url of the SurrealDB record id,
  without padding. General `app/db/ids.py` (`encode_rid` / `decode_rid`) is planned in 2.2.2;
  auth currently uses the narrow typed `app/domain/identity.py` helpers for scalar user IDs.
  Decoding validates the expected table and canonical encoding.
- Lists use `?limit=&cursor=` and return `{ items, next_cursor }`.
- Errors: HTTP status plus `{ "code": "project.not_found", "message": "...", "field": null }`. The
  frontend shows `t('errors.' + code)`.
- Framework HTTP errors use `http.<lowercase_status_name>` (`http.error` for unknown statuses);
  unexpected errors use `internal.error` and a generic message. They emit an `unhandled_error`
  structured log with the request ID and exception type, not the exception message or request data.
  Once that 500 is fully sent, only its handled exception is consumed; cancellation and errors
  after a response starts still propagate.
- Request validation errors use `validation.invalid` and include the first invalid field, with
  nested fields separated by dots; `field` is null when no field can be identified.
- Each response includes an `X-Request-ID` generated by the API middleware and attached to
  request-scoped structured logs.
- Async operations return `202 { job_id }`. `GET /api/jobs/{id}` returns the status.

## Git

- Branches: `main`, plus `task/X.Y.Z-short-slug` per task. No other long-lived branches.
- Commits: Conventional Commits with the task ID as scope: `feat(1.5.3): login and refresh endpoints`,
  `fix(2.4.1): …`, `docs(plan): …`, `chore`, `refactor`, `test`.
- Merges: `--no-ff` with the message `merge: task X.Y.Z <title>`.
- `./scripts/dev.ps1 setup` installs lefthook into the main worktree's shared Git hooks directory.
  It enables Node TLS certificate verification for package installation.
  Running a hook does not synchronize hooks automatically; run `pnpm exec lefthook install` from
  main when installation or a hook update is needed. Dependencies are per worktree: use
  `uv sync --project backend` and `pnpm install --ignore-scripts` in a linked worktree to avoid
  lefthook's package postinstall changing the shared hooks.
- Before a commit, lefthook runs `ruff format --check`, `ruff check` and ESLint on the staged
  contents of Python, TypeScript and Vue files, including partially staged files. It does not modify
  or stage files. The check uses the backend Ruff and frontend ESLint configurations.
- The environment-file guard blocks staged paths containing an `.env*` component, including
  force-added ignored files. Only a file named exactly `.env.example` is allowed; deleting a
  previously tracked environment file is allowed.
- Run `pwsh -NoProfile -File ./scripts/tests/lefthook.test.ps1` to exercise the hook in a disposable
  Git repository under `.dev/`. It uses synthetic environment files and removes the repository.
